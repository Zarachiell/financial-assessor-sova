# Fase 7.5 — Comprovantes de pagamentos planejados

## Estado

Implementada em 30/08/2026.

## Objetivo

Vincular uma imagem enviada com legenda a uma liquidação real de fluxo de caixa e permitir que o comprovante seja consultado posteriormente.

## Entregue

- tabela `settlement_receipts` com vínculo obrigatório a `cash_flow_settlements` e `attachments`;
- foreign keys compostas para impedir vínculos entre households;
- autoria, legenda e instante do vínculo;
- múltiplos comprovantes por liquidação e idempotência por anexo;
- fluxo orquestrado que primeiro liquida a ocorrência e depois vincula o comprovante;
- tool `link_settlement_receipt` para vínculo explícito;
- tool `get_settlement_receipts` para consulta de metadados e acesso posterior;
- links temporários assinados para recuperar a mídia;
- resposta HTTP com `no-store`, `nosniff` e validação de integridade antes da entrega;
- testes de idempotência, autorização, integridade e recuperação.

## Regra operacional

O comprovante documenta uma liquidação. Ele não altera caixa sozinho: a saída de dinheiro continua sendo criada atomicamente pelo command de liquidação, junto com a `Transaction` e o `CashFlowSettlement`.

## Armazenamento

O PostgreSQL guarda apenas metadados e relacionamentos. O binário fica em volume persistente configurado por `SOVA_MEDIA_STORAGE_PATH`. A abstração `MediaStorage` permite trocar esse adapter por object storage no futuro sem mudar o domínio.

## Critérios de aceite

- somente anexos processados do mesmo household podem ser vinculados;
- repetir o mesmo vínculo não cria duplicata;
- uma liquidação aceita mais de um comprovante distinto;
- links inválidos ou expirados retornam `404`;
- adulteração do arquivo é detectada pelo SHA-256;
- a consulta pelo Sova retorna metadados e URL temporária, nunca um caminho interno.
